# Assignment 2 — Travel Planner Agent Evaluation

## Objective
Evaluate the Travel Planner Agent from Assignment 1 across different user requests and identify areas for improvement.

## Evaluation approach
This package contains 12 test cases covering normal trips, different destinations/durations/budgets, missing information, invalid inputs, preferences, time-sensitive requests, and an out-of-scope request.

Each response is scored from 0–1 on:
1. Correctness
2. Relevance
3. Completeness
4. Tool Usage

`Overall Test Score = (Correctness + Relevance + Completeness + Tool Usage) / 4`

`Overall Evaluation Score = mean of all test-case scores`

## Test cases
TC01 valid 3-day Jaipur; TC02 valid 5-day Delhi; TC03 low-budget Rishikesh; TC04 missing destination; TC05 missing budget; TC06 invalid days; TC07 negative budget; TC08 historical preference; TC09 vegetarian food preference; TC10 non-travel question; TC11 current Japan visa; TC12 current Eiffel Tower information.

## Run
Install the main project's requirements, then from this folder run:
```bash
python evaluator.py --run
```
This populates `evaluation_results.json` with actual responses and scores.

The included heuristic evaluator is a transparent baseline. It should not be presented as a human-quality semantic judge.

## Gemini LLM-as-a-Judge bonus
Install:
```bash
pip install google-genai
```
Set `GEMINI_API_KEY` or `GOOGLE_API_KEY` as an environment variable, never in source control, then:
```bash
python gemini_judge.py
```
Example output:
```text

Correctness: 0.90
Relevance: 1.00
Completeness: 0.80
Tool Usage: 1.00

Reason: The response satisfies the destination, duration, budget and preferences.
```

## Overall score / failures
`evaluation_results.json` is an artifact generated by the evaluator. The supplied ZIP intentionally does **not invent a score before the real agent is run**. After `python evaluator.py --run`, it records the overall score and failed test cases (baseline failure threshold: <0.75).

## Suggestions for improving the agent
- Validate duration and budget before LLM generation.
- Ask concise clarification questions for missing critical fields.
- Use structured itinerary output for easier evaluation.
- Trigger web search only for time-sensitive requests to reduce latency.
- Prefer official sources for visa, attraction and transport information.
- Add regression tests for budgets and dates.
- Use semantic LLM judging for itinerary quality.
- Track response latency and token usage.
